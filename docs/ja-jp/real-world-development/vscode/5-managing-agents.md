GitHub Copilot を Agent Mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。Copilot はローカル環境でリアルタイムに作業するため、VS Code の Copilot Chat には各ツール呼び出しやファイル編集の進行状況が表示されます。差分をインラインで確認し、個々の変更を承認または拒否できます。また、エディターを離れずに追加のプロンプトを送信して、作業を改善したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して承認します。
- セッション中にエージェントの方向を調整し、ハイ コントラストに加えてライト モードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライト モードの切り替え機能も追加してほしいとのことです。新しい会話を最初から始めずに、既存のセッションを調整して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集などを確認できます。各ファイルの編集内容は、差分と **Keep** / **Undo** のコントロールとともにインラインで表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み込み、編集、実行を求めるターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を元に戻して、エージェントに再度作業してもらうには **Undo** を選択します。
4. チャットの上部にある **Files changed** を開き、このセッション中にエージェントが変更したすべてのファイルを確認することもできます。

> [!NOTE]
> ツール呼び出し (ターミナル コマンドの実行など) に許可が必要な場合、エージェントは一時停止し、**Allow** の確認を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。最後に、変更内容の概要が表示されます。

## ライト モードを追加するようエージェントを調整する

ハイ コントラスト モードの実装が完了したら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは前の作業のコンテキストを引き継ぎます。変更したコンポーネント、スタイルの方針、設定を保存するために使った local storage のパターンなどが含まれます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業を続け、すでに行った変更を調べて、ライト モードの追加を提案します。
3. ハイ コントラスト モードのときと同じように、新しい編集内容を確認します。差分ごとに **Keep** または **Undo** を使います。
4. エージェントの進め方が希望と異なる場合 (たとえば、好みでない方法でトグル UI をリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加メッセージを送信します。

> [!TIP]
> 実行中のセッションを調整すると、最初からやり直すよりも速く作業できます。追加プロンプトを使って調整 ("CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使ってください")、軌道修正 ("3 つ目のトグルは追加せず、既存の設定パネルにライト モードを統合してください")、作業範囲の拡張 ("両方のトグルにキーボード ショートカットも追加してください") を依頼できます。

## 作業ファイルを確認する

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが表示されます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

この演習では、Copilot Chat の Agent Mode を使って、進行中のセッションを監視し、方向を調整しました。ファイル編集の差分を確認して承認または拒否し、コンテキストを保ったまま追加プロンプトを送信して作業を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または拒否しました。
- セッション中に追加プロンプトを送信して、作業の方向を調整しました。
