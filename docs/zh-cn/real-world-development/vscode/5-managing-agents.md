当 GitHub Copilot 处于代理模式时，它会自主工作：探索代码库、提出更改、编辑文件并运行命令。由于 Copilot 会在你的计算机上实时工作，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以直接在聊天中查看每个差异，接受或拒绝单项更改，也可以通过后续提示引导对话、完善或扩展工作，全程无需离开编辑器。

在本练习中，你将：

- 实时监视无障碍代理的工作；
- 审查并接受建议的文件编辑；
- 在会话进行中引导代理，在高对比度模式之外添加浅色模式切换开关。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义代理正在实现高对比度模式。工作进行期间，设计团队又提出了一项要求：他们希望为觉得默认主题太暗的用户添加浅色模式切换开关。无需从头开始新对话，你可以引导当前会话继续完成这项工作。

## 监视 Copilot 的进度

Copilot Chat 视图会显示代理执行的每个步骤，包括探索的文件、运行的命令和建议的编辑。每项文件编辑都会在聊天中内嵌显示差异，并提供 **Keep** / **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 代理工作时，在聊天中滚动查看每次工具调用。你会看到文件读取、文件编辑，以及它请求运行的终端命令。
3. 代理提出文件编辑时，差异会内嵌显示：
    - 选择 **Keep** 接受更改。
    - 选择 **Undo** 撤销更改，让代理重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看代理在此会话中修改的全部文件。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），代理会暂停并显示 **Allow** 提示。只批准你信任的命令。

5. 等待代理完成高对比度模式的实现。完成后应会看到一条总结所做更改的消息。

## 引导代理添加浅色模式

现在高对比度模式已经就绪，可以继续在同一对话中添加浅色模式切换开关。由于继续使用同一个聊天会话，代理会保留之前工作的所有上下文，包括修改过的组件、采用的样式方案和设置的本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在在高对比度切换开关旁边添加浅色模式切换开关。浅色模式应采用相同模式：使用 local storage 保存设置，并且可以从 UI 的同一区域访问。用户应能够独立启用高对比度模式和浅色模式。
    ```

2. 代理会接着之前的工作继续探索已做的更改，并提出添加浅色模式的方案。
3. 像审查高对比度模式时那样，逐项检查新编辑。使用 **Keep** 或 **Undo** 处理每个差异。
4. 如果代理的工作方向不符合预期，例如它尝试以你不喜欢的方式重构切换开关 UI，可以选择聊天输入框旁边的 **Stop** 按钮停止工作，然后发送说明情况的后续消息。

> [!TIP]
> 引导正在进行的会话比从头开始更快。可以使用后续提示要求调整（“简化 CSS——使用 CSS 变量，而不是重复选择器”）、纠正方向（“不要添加第三个切换开关，把浅色模式集成到现有设置面板中”），或扩展范围（“还要为两个切换开关添加键盘快捷键”）。

## 审查工作集

提交更改之前，快速检查代理修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 查看已更改文件的完整列表。你应该会看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改的文件并查看差异。确认其中体现了自定义代理提供的无障碍模式，包括 ARIA 属性、键盘导航、语义化 HTML 和通过本地存储持久化设置。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和下一步

本课中，你使用 Copilot Chat 代理模式监视并引导了正在进行的会话：检查逐项应用的文件编辑、接受或拒绝更改，并在保留上下文的同时发送后续提示来扩展工作。

本课介绍了以下内容：

- 实时监视代理工作；
- 接受或拒绝单项文件编辑；
- 在任务进行期间引导会话。

在[下一课][next-lesson]中，你将把无障碍相关工作发布为拉取请求，并审查本实验中本地自定义代理所做的更改。
